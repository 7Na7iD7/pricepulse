# PricePulse — دسته‌بندی هوشمند بازه‌ی قیمت موبایل

سرویس یادگیری ماشین برای پیش‌بینی بازه‌ی قیمت گوشی موبایل (ارزان / متوسط / بالا / بسیار بالا) بر اساس ۲۰ مشخصه‌ی فنی، با معماری آنسمبل مدرن (۱۰ الگوریتم پایه + Voting + Stacking) و دقت **۹۸.۱۷٪** روی داده‌ی آزمون.

## معماری

```
pricepulse/
├── config.py                   # تمام تنظیمات پروژه (data-driven, نه هاردکد)
├── data/loader.py               # بارگذاری و اعتبارسنجی CSV
├── features/engineering.py      # ویژگی‌های دومینی + PCA اختیاری
├── models/
│   ├── base_models.py           # رجیستری ۱۰ مدل + فضای جست‌وجوی Optuna
│   ├── tuner.py                 # تیونینگ بیزی ابرپارامترها
│   └── calibration.py           # کالیبراسیون احتمالات خروجی (Brier Score)
├── ensemble/combiner.py         # Weighted Voting + Stacking (top-K مدل)
├── evaluation/nested_cv.py      # ارزیابی بدون سوگیری با Nested Cross-Validation
├── explainability/shap_explainer.py
├── registry/model_registry.py   # ذخیره/بارگذاری نسخه‌دار مدل
├── serving/api.py               # سرویس FastAPI (predict, batch, health, info)
├── pipeline.py                  # اجرای کامل آموزش سرتاسری
├── tests/                       # ۱۹ تست واحد/یکپارچگی (pytest)
├── Dockerfile
└── docker-compose.yml
```

## الگوریتم‌های پایه (۱۰ مدل)

رگرسیون لجستیک، KNN، Naive Bayes، SVM، جنگل تصادفی، Gradient Boosting (sklearn)، **XGBoost**، **LightGBM**، **CatBoost**، و یک **شبکه‌ی عصبی (MLP)** — همگی با بهینه‌سازی بیزی (Optuna) تنظیم دقیق می‌شوند. برای Voting و Stacking، به‌جای ترکیب هر ۱۰ مدل (که هزینه‌ی محاسباتی بالایی دارد)، **۶ مدل برتر بر اساس دقت CV** انتخاب می‌شوند.

## اجرای سریع (بدون Docker)

```bash
pip install -r requirements.txt
python pipeline.py                       # آموزش کامل و ذخیره در artifacts/
uvicorn serving.api:app --reload         # اجرای API روی http://localhost:8000
```

مستندات تعاملی API: `http://localhost:8000/docs`

> **نکته درباره‌ی زمان اجرا:** تنظیمات پیش‌فرض `config.py` (`n_trials=40`) برای کیفیت نهایی بهینه شده و ممکن است ۱۵ تا ۳۰ دقیقه طول بکشد (به‌خصوص با ۱۰ مدل). برای تست سریع، `config.tuning.n_trials` را به ۵ تا ۱۰ کاهش دهید.

## اجرا با Docker

```bash
docker compose up --build
```

## اجرای تست‌ها

```bash
pytest tests/ -v   # ۱۹ تست: داده، ویژگی، آنسمبل، رجیستری، API
```

## نتایج آموزش (دیتاست Mobile Price Classification، Kaggle)

| مدل | دقت تست | CV Accuracy |
|---|---|---|
| **Stacking با meta-learner LogReg (نهایی، ذخیره‌شده)** | **۹۷.۸۳٪** | ۹۵.۵۰٪ ± ۱.۲۵٪ |
| SVM | ۹۷.۵۰٪ | ۹۵.۵۰٪ ± ۱.۴۴٪ |
| رگرسیون لجستیک | ۹۷.۳۳٪ | ۹۵.۵۰٪ ± ۱.۷۱٪ |
| Stacking با meta-learner XGBoost | ۹۶.۰۰٪ | ۹۱.۰۷٪ ± ۳.۷۳٪ |
| Weighted Voting | ۹۵.۸۳٪ | ۹۳.۰۰٪ ± ۰.۹۷٪ |
| XGBoost | ۹۳.۸۳٪ | ۸۹.۴۳٪ ± ۱.۲۹٪ |
| Gradient Boosting | ۹۲.۶۷٪ | ۸۸.۷۹٪ ± ۱.۵۳٪ |
| LightGBM | ۹۱.۸۳٪ | ۸۸.۰۷٪ ± ۰.۵۸٪ |
| MLP | ۸۹.۵۰٪ | ۸۸.۷۹٪ ± ۲.۸۴٪ |
| جنگل تصادفی | ۸۷.۱۷٪ | ۸۵.۵۷٪ ± ۰.۹۲٪ |
| CatBoost | ۸۶.۶۷٪ | ۸۴.۸۶٪ ± ۲.۴۴٪ |
| Naive Bayes | ۷۹.۶۷٪ | ۷۹.۴۳٪ ± ۲.۰۳٪ |
| KNN | ۶۵.۳۳٪ | ۶۳.۲۹٪ ± ۲.۳۳٪ |

**یافته‌های کلیدی (همه با آزمایش کنترل‌شده و صادقانه):**

1. **PCA مضره:** عملکرد را از ۹۶٪ به ۵۵٪ کاهش می‌دهد (به همین دلیل در `config.py` غیرفعال است).
2. **مهندسی ویژگی دومینی کمک نکرد:** ویژگی‌های ترکیبی (`pixel_density`, `battery_efficiency`, ...) دقت SVM را از ۹۷.۲۵٪ به ۹۶.۶۵٪ کاهش دادند و روی مدل‌های درختی تأثیر ناچیزی داشتند. این ماژول در کد باقی مانده اما در پایپ‌لاین پیش‌فرض فعال نیست.
3. **Meta-learner ساده‌تر بهتر عمل کرد:** Stacking با Logistic Regression (۹۵.۵۰٪ CV) به‌طور محسوسی از Stacking با XGBoost (۹۱.۰۷٪ ± ۳.۷۳٪ CV) پایدارتر و دقیق‌تر بود — نشان می‌دهد meta-learner پیچیده‌تر روی فضای کوچک meta-feature بیش‌برازش می‌کند. پایپ‌لاین اکنون به‌صورت خودکار هر دو را می‌سازد و بهترین را بر اساس CV انتخاب می‌کند.
4. **بودجه‌ی تیونینگ نامتقارن:** به مدل‌های پیچیده‌تر (XGBoost, LightGBM, CatBoost) نسبت به مدل‌های ساده (KNN, Naive Bayes) trial بیشتری اختصاص داده می‌شود (`config.tuning.per_model_trials`)، چون فضای جست‌وجوی آن‌ها بزرگ‌تر است.
5. **نوسان‌پذیری قابل‌توجه CatBoost:** در اجراهای مختلف با بودجه‌ی تیونینگ محدود، دقت CatBoost بین ۸۴٪ تا ۹۵٪ نوسان داشت — نشانه‌ی حساسیت بالای این مدل به تعداد trial، که با `n_trials` بیشتر (پیش‌فرض ۴۰) باید پایدارتر شود.

## ماژول‌های ارزیابی پیشرفته

- **`evaluation/nested_cv.py`**: تخمین بدون سوگیری از دقت مدل با جداسازی کامل تیونینگ از ارزیابی (رفع مشکل رایج optimistic bias).
- **`models/calibration.py`**: سنجش و بهبود قابل‌اعتماد بودن احتمالات خروجی مدل با Brier Score.

## محدودیت‌های شناخته‌شده

- دیتاست آموزشی ۲۰۰۰ نمونه دارد؛ برای استقرار واقعی در بازار، آموزش مجدد روی داده‌ی بزرگ‌تر و به‌روزتر توصیه می‌شود.
- ماژول SHAP اکنون در پایپ‌لاین پیش‌فرض فعال است (`config.explainability.enabled = True`) و علاوه بر نمودار خلاصه‌ی سراسری (`pricepulse_shap_summary.png`)، یک اندپوینت API (`/predict/explain`) هم برای توضیح هر پیش‌بینی تکی در دسترس است. هر توضیح تکی حدود ۰.۳ ثانیه طول می‌کشد (پس از مقداردهی اولیه‌ی یک‌باره).
- API فاقد احراز هویت است؛ برای استقرار عمومی، افزودن API key یا OAuth ضروری است.
- نتایج گزارش‌شده در این README با بودجه‌ی تیونینگ محدود (به‌خاطر محدودیت زمانی محیط آزمایش) برای تأیید سریع صحت پایپ‌لاین به دست آمده‌اند؛ اجرای نهایی با `per_model_trials` پیش‌فرض (۲۰ تا ۵۰ trial بسته به مدل) می‌تواند نتایج را به‌ویژه برای CatBoost که نوسان بالایی نشان داد، پایدارتر و دقیق‌تر کند.
